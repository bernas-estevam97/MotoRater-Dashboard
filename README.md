# 🐁 MotoRater Suite

[![Streamlit App](https://static.streamlit.io/badges/streamlit_badge_black_white.svg)](https://motorater-dashboard.streamlit.app/)

An advanced, high-performance [Streamlit](https://streamlit.io/) application designed for the visualization, exploration, and longitudinal statistical modeling of locomotion and kinematic data generated by the **MotoRater** apparatus.

> 🌐 **Live Web Application:** Access the suite instantly without installation at **[motorater-dashboard.streamlit.app](https://motorater-dashboard.streamlit.app/)**.

All data processing pipelines, experimental filtering algorithms, and statistical decision engines are developed and maintained by **Bernardo Estevam**.

## 🌟 Suite Overview & Capabilities

The MotoRater Suite provides an integrated research platform with tools tailored for both rapid exploratory checks and publication-grade statistical analysis:

| Tool | Format | Purpose | Key Capabilities |
| :--- | :--- | :--- | :--- |
| **📈 Time-Series Analysis (Excel)** | `.xlsx`, `.xls` | Exploratory time-series visualization from Excel files | Single & multi-file comparison, rolling-average noise filtering, polar angle plots, descriptive statistics, and correlation heatmaps. |
| **📈 Time-Series Analysis (Parquet / HDF5)** | `.parquet`, `.h5`, `.hdf5` | High-speed time-series analysis for large datasets | **Up to 50x faster loading** than Excel, low RAM footprint, multi-dataset inspection. |

| **⚡ Excel ➔ Parquet/HDF5 Converter** | `.xlsx` ➔ `.parquet` / `.h5` | Batch file converter & compressor | Converts multi-sheet Excel files into optimized Parquet tables (or HDF5 stores) with automated kinematics data cleaning. |
| **🧮 Statistical Methodology** | In-app Guide | Statistical reference & paper writing guide | Detailed breakdown of assumptions, normality tests, sphericity corrections, and copy-paste methods templates for scientific papers. |

## 🚀 Dual-Mode Operation & Branch Architecture

The MotoRater Suite offers two usage modes depending on whether you prefer instant zero-install cloud access or local offline workstation processing:

| Feature / Capability | ☁️ Streamlit Cloud (`dev-cloud` branch) | 💻 Local Standalone Workstation (`dev` branch) |
| :--- | :--- | :--- |
| **Access / Setup** | **[motorater-dashboard.streamlit.app](https://motorater-dashboard.streamlit.app/)** (Instant) | Clone `dev` branch + local dependencies |
| **Installation** | **Zero installation required** | Python 3.10+ (or automated `.bat` / `.command` scripts) |
| **File Input** | Drag-and-drop browser file uploaders (`st.file_uploader`) | Native OS folder dialogs / direct directory paths |
| **File Export** | In-browser ZIP download buttons | Direct output saving to local folders |
| **Hardware & Performance** | Shared Cloud container resources (safe upload limits) | Full multi-core CPU & RAM offline workstation performance |
| **Ideal For** | Quick checks, sharing with collaborators, remote access | Large longitudinal studies, bulk trial processing, offline labs |

### Why Are There Two Separate Branches (`dev` vs. `dev-cloud`)?
In a local desktop environment, the application can leverage full operating system capabilities: opening native OS folder selection dialogs, scanning local disk hierarchies, saving converted Parquet/HDF5 files directly to disk folders, and utilizing local multi-core CPUs and RAM.

However, in the hosted, sandboxed web container of **Streamlit Cloud (Free tier)**, these same desktop elements (such as launching native OS file dialogs or saving directly to local desktop paths) do not work and would cause web session errors.

To address this, two dedicated branches are maintained:
1. **`dev-cloud` Branch (Streamlit Cloud):**
   * Adapted specifically for the free hosted environment on Streamlit Community Cloud.
   * Replaces local folder paths and desktop dialogs with cloud-safe drag-and-drop file uploaders (`st.file_uploader`).
   * Uses in-memory file conversion buffers (`BytesIO`) with direct browser download buttons for converted ZIP archives.
   * Includes server capacity counters and memory safeguards to prevent container crashes.
   * **Live at:** [https://motorater-dashboard.streamlit.app/](https://motorater-dashboard.streamlit.app/)
2. **`dev` Branch (Local Standalone Workstation):**
   * Configured for high-performance offline research on personal computers or lab workstations.
   * Features native folder pickers, direct batch folder scanning, direct output saving to local directories, and local hardware monitoring.
   * Includes 1-click launch scripts (`Launch_Dashboard.bat`, `Launch_Dashboard.command`) for automated setup and launch.

> [!TIP]
> **Which option should you choose?**
> - **Use Streamlit Cloud** (visit [motorater-dashboard.streamlit.app](https://motorater-dashboard.streamlit.app/)) if you want instant, zero-setup access to visualize files or run quick analyses from any device.
> - **Use the Local Workstation (`dev` branch)** if you work with massive datasets (gigabytes of high-frequency kinematics), need to batch-process entire local directories directly to disk, or work in an offline lab environment.

## 🛠️ Quick Start & Installation

### 🌐 Option 1: Instant Browser Access (Streamlit Cloud — No Installation)
You do not need to install Python or clone the repository to use the application:
👉 **[Open MotoRater Dashboard on Streamlit Cloud](https://motorater-dashboard.streamlit.app/)**

---

### 💻 Option 2: Windows Automated Launchers (`dev` branch)
Place the repository folder onto your local machine (from the `dev` branch) and run:
* **`Launch_Dashboard.bat` (First Run & General Launch)**
  * Automatically detects if a virtual environment (`venv`) already exists.
  * If no environment is found, automatically installs an isolated, portable Python 3.12 environment, verifies all dependencies, and launches the app.
* **`Update_Launch_App.bat` (Daily Use)**
  * Offers an optional 4-second prompt to check GitHub for the latest updates before launching the application.
* **`Updater.bat` (Standalone Background Updater)**
  * Fetches and applies the latest updates from GitHub without starting the application.

### 🍎 Option 3: macOS Automated Launcher (`dev` branch)
* Open Terminal in the repository folder:
  ```bash
  chmod +x Launch_Dashboard.command
  ```
* Double-click **`Launch_Dashboard.command`** to create the virtual environment, install dependencies, and launch the suite.

### ⚙️ Option 4: Manual Local Installation (`dev` branch)
```bash
# 1. Clone repository and checkout the dev branch
git clone -b dev https://github.com/bernas-estevam97/MotoRater-Dashboard.git
cd MotoRater-Dashboard

# 2. Create and activate virtual environment
python -m venv venv
# On Windows:
venv\Scripts\activate
# On macOS / Linux:
source venv/bin/activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Launch the application
streamlit run main.py
```

## ⚡ Performance Tips: Why Does First Load Take a Moment?

### 1. Cold-Start Imports & Background Pre-Warming
* **Why it happens:** Heavy scientific packages (`pingouin`, `statsmodels`, `scipy`, `openpyxl`) require 5–10 seconds on the very first execution of a fresh Python process to compile and index into memory.
* **Built-in Optimization:** The suite includes an automatic background **Pre-Warmer** in `main.py`. While you view the Welcome landing page, heavy modules are silently loaded into memory so that navigating to the Kinematics or Time-Series tools is fast and responsive.

### 2. Excel vs. Parquet Speed Difference
* Raw `.xlsx` files are zipped XML documents that require significant CPU time to decompress and parse.
* **Tip:** For large experimental datasets, run your Excel files through the **⚡ Excel ➔ Parquet Converter** once. Parquet files load in **~0.05 seconds** (50x faster) and use a fraction of system RAM.

### 3. Freeing Memory
* When comparing dozens of high-frequency locomotion trials, click the **`🧹 Clear Server Cache`** button in the sidebar to release RAM and purge stale DataFrames from cache.

## 🧮 Statistical Decision Tree

When analyzing longitudinal data in the **Kinematics Longitudinal Analyzer**, the suite applies an automated statistical pipeline:
* **Single Timepoint (Cross-Sectional):**
  * Evaluates residual normality via the Shapiro-Wilk test.
  * **Parametric:** Welch's Independent t-test (robust to unequal variances).
  * **Non-Parametric:** Mann-Whitney U test.
* **Two or More Timepoints (Longitudinal):**
  * **Pipeline A (2-Way Mixed ANOVA):** Triggered when data is normally distributed and perfectly balanced. Applies Mauchly's sphericity test with Greenhouse-Geisser correction (`p-GG-corr`).
  * **Pipeline B (Linear Mixed-Effects Models - LMM):** Triggered when data is normal but has missing timepoints or dropouts, preventing Survivor Bias without dropping animals.
  * **Pipeline C (Generalized Estimating Equations - GEE):** Triggered when normality assumptions are violated (skewed data). Uses robust Sandwich estimators and Wald contrast tests.
* **Multiple Comparisons:** All post-hoc p-values are adjusted using the **Holm-Bonferroni** or **FDR (Benjamini-Hochberg)** step-down methods.

## 🌿 Branching Strategy

* **`dev` Branch (Local Workstation):** The primary active branch for local execution. Features native folder dialogs, direct filesystem output, automated launcher scripts (`.bat` / `.command`), and multi-core processing for large datasets.
* **`dev-cloud` Branch (Streamlit Cloud):** The active branch deployed directly to [Streamlit Community Cloud (Free tier)](https://motorater-dashboard.streamlit.app/). Contains cloud-adapted file uploaders, in-memory buffers (`BytesIO`), ZIP download buttons, and container memory safeguards.
* **`master` Branch:** Legacy baseline repository (contains initial project commit; all active development and enhancements are maintained on `dev` and `dev-cloud`).
