## 1. Project Overview & Architecture

MotoRater Dashboard is a Streamlit-based suite designed for the visualization, analysis, and longitudinal modeling of experimental locomotion data generated by the MotoRater apparatus.

The codebase now operates in a unified **dual-mode architecture**:
1. **Streamlit Cloud Deployment:** A cloud-hosted environment (running headless on Linux) launched via `main.py` and `st.navigation`, with automatic headless detection that defaults to standard browser-based file uploaders (`st.file_uploader`).
2. **Local Standalone Deployment:** A portable or venv-based setup for workstations on Windows and macOS, launched via automated batch scripts (`Launch_Dashboard.bat`, `Update_Launch_App.bat`, `Launch_Dashboard.command`) with smart environment detection (utilizing existing `venv\` or portable `python_env\`), native desktop folder picking, and full dependency verification.

### G. Prism-Style Statistics Engine (`prod_pro`, 2026-10-12)
* New `scripts/utils/stats_engine.py` holds all statistics as pure functions, shared by the page, the Streamlit cache
  and the parallel batch exporter (previously the batch exporter used a different model than the page).
* Users choose the **test**, **post-hoc** and **correction** (and α); *Auto* keeps the original decision tree.
  - 2 groups / 1 timepoint: Welch's t, Student's t, Mann-Whitney U.
  - 3+ groups / 1 timepoint: one-way ANOVA (Tukey, pairwise t/Welch), Welch ANOVA (Games-Howell, pairwise Welch),
    Kruskal-Wallis (Dunn, pairwise Mann-Whitney).
  - 2+ timepoints: RM ANOVA (mixed design, GG-corrected), mixed-effects model (REML), GEE (family + working correlation
    selectable), or any cross-sectional test per timepoint. Post-hoc = model-based contrasts for every group pair.
  - Corrections: Holm, Šídák, Holm-Šídák, Bonferroni, BH-FDR, two-stage BKY, none.
* `assess_fit()` warns when a choice does not fit the data (non-normal residuals with parametric tests, unequal
  variances with Student/ordinary ANOVA/Tukey, RM ANOVA with missing timepoints, per-timepoint tests on repeated
  measures, no correction with many comparisons) and blocks overlapping groups.
* Fixes: mixed-model fitting now tries several optimizers (lbfgs alone hit singular matrices and silently fell back to
  OLS); model contrasts are built from the fitted model's design rows so they work for any group pair; omnibus tests for LMM/GEE use
  sum-to-zero coding (Type III-style Wald χ²); HDF5 uploads now load (HDFStore cannot read a BytesIO buffer).

### J. Library Compatibility Fixes (`prod_pro`, 2026-10-20, ported from `pro-cloud`)
* Root cause: `requirements.txt` had no version bounds, so any fresh install (Streamlit Cloud, or the launchers
  re-installing dependencies) got statsmodels 0.15 / pandas 3 / polars 2, while the existing local venv stayed on
  statsmodels 0.14.6 / pandas 2.3. Found on Cloud first; same code, so fixed here too.
* **RM ANOVA, mixed-effects model and GEE failed** with `'PandasData' object has no attribute 'design_info'`
  (statsmodels 0.15 removed it). `_model_contrasts` now takes each time × group design row from the fitted model's
  own `exog`, so it no longer depends on patsy internals. Unused `patsy` import removed.
* **Kinematics page crashed the Python process** (access violation in `pl.from_pandas`, polars 2.0 + pandas 3).
  `build_final_df` now uses the same pandas merge / mean as the batch exporter. polars removed from the page,
  the `main.py` pre-warm and `requirements.txt`.
* **GEE with Autoregressive working correlation failed** on some data:
  - statsmodels sets the AR parameter to int `0` when the lag-1 correlation is ~0, which crashes for subjects with
    exactly 2 observations. A small `_Autoregressive` subclass casts it to float.
  - When AR(1) cannot be estimated (correlation ~1), the fit now falls back to Exchangeable with a warning, also when
    Autoregressive was chosen explicitly (previously only in Auto mode).
* `requirements.txt` now uses version ranges between the two tested sets (local venv and latest Cloud releases), with
  caps below untested major releases. Removed packages the app never imports: `polars`, `xarray`, and the pingouin
  dependencies `scikit-learn`, `seaborn`, `pandas-flavor` (pingouin installs them itself). `psutil` stays on this
  branch (memory monitor in the local time-series pages). The pinned set needs **Python 3.11+**.
* Launchers: install checks no longer import `polars` (a fresh install would otherwise fail verification).
  `Launch_Dashboard.command` stops with a clear message when the Mac's `python3` is older than 3.11, and its fallback
  package list matches `requirements.txt`. `Launch_Dashboard.bat` already downloads Python 3.12.
* Verification: `stats_engine.py` self-check (new GEE AR(1) regression case) passes on statsmodels 0.14.6 and 0.15.0;
  21 cross-checks against scipy / statsmodels / pingouin / hand calculations pass on both; a scripted Streamlit
  `AppTest` run of 870 page interactions (tests, post-hocs, corrections, GEE options, plot settings, units, batch
  export) on the latest Cloud package set showed no crash or exception.
* Recommendation no longer contradicts its own fit check:
  - **GEE small samples:** with < 40 subjects (`GEE_SMALL_N`) GEE now uses Mancl-DeRouen bias-reduced sandwich
    standard errors (`cov_type='bias_reduced'`). The former "optimistic p-values" warning is now an info note, and the
    methods text names the correction.
  - **< 3 subjects in a group with 2+ timepoints:** Auto used to recommend a repeated-measures model that the fit check
    then blocked (nothing ran). It now recommends the matching per-timepoint test and says why.
  - Both cases are covered by the `stats_engine.py` self-check; `stat_info.py` text updated.

### K. Progression Model & Cohort Handling (`prod_pro`, 2026-11-17)
Motivation: on the SCA2 footprint data, per-timepoint tests found almost nothing, while a continuous-age model found a
progressive TG decline (Protraction/Retraction, Knee Angle) and higher TG pelvic variability (SD/CV of hip, iliac
crest, tail base height). Cohorts started at different times and the camera setup changed (week 44 for cohorts 1–5,
week 16 for cohort 6), which shifted height measurements by recording day.
- **`progression` test** (`stats_engine._fit_progression`): `y ~ age * group + age²` [+ setup], age centred and scaled
  internally, results reported per week. Random subject intercept + age slope; with 2+ cohorts, cohort is the grouping
  factor with variance components for subject, subject slope and session (cohort × timepoint). Falls back to random
  intercepts if slopes fail. Reports *Level difference at week c* and *Rate difference per week* vs the reference
  group; optional log-transform adds `% difference`.
- **Cohort table** (Groups & Subjects, optional): Cohort | Animal IDs | New setup from week → `Cohort` / `Setup` columns
  via `apply_cohorts()`; ignored by all other tests.
- **L/R averages** (sidebar): `(L/R mean)` columns for every Left/Right pair (`add_lr_means`).
- **Log-transform** checkbox for the progression model, default on for SD/CV sheets (`is_variability_sheet`).
- **CV warning** when a CV-sheet measurement has negative values (signed components, toe clearance).
- **Batch export**: measurement multiselect (primary outcomes) and `p_corr_all_measurements` column.
- **Fix**: uploading a corrected file with the same name now resets the session (keyed on content hash, not name).
- Display: tables show 4 significant digits instead of 4 decimals (small per-week effects were shown as 0.0000).

### L. Metadata Extraction, Covariates & Data-Quality Checks (`prod_pro`, 2026-11-17)
From a full-app review against the SCA2 footprint data (L/R height correlation 0.07, 10° knee-angle side offset,
broken left hindpaw toe clearance, ~6% half-length Step Length sessions, run duration 0.8–8 s).
- **A** `Protraction/Retraction` relabelled `(m)`: it is the Euclidean hind toe → PSIS distance, not an angle
  (now also converted by the m→mm switch).
- **B** `(L/R mean)` measurements warn when the two sides disagree (r < 0.5 or means > 20% apart): `lr_disagreement()`.
- **C** 95% CIs (`se.CI_LO/CI_HI`) for model contrasts (`t_test().conf_int`), progression (Wald z) and t-tests
  (`ttest_ind().confidence_interval`); `% CI` columns under log-transform; methods text mentions them.
- **D** Progression covariate: any numeric column of any sheet (`se.COV`, z-scored, "per SD"); sessions without a value
  are dropped with a note.
- **E** `Adjust for sex` (`se.SEX`): from a metadata column or an `M`/`F` token in the ID.
- **F** Single-session exclusion (`exclude_sessions_ui`, label "animal @ week") and an outlier panel: robust z > 5 vs
  group × week median + the animal's own offset (follows growth), with a button that adds them to the exclusion list.
- **G** Metadata mode: pick subject / timepoint / group(s) / sex columns + weeks-per-timepoint factor. Every sheet
  gets an `Ids` = `subject|timepoint` row key (`with_row_keys`), so the rest of the page is unchanged. Rows with an
  animal in two groups are listed (labelling errors). `metric_columns` now skips metadata / non-numeric columns.
- **H** Fitted population-average trend (`details['trend']`, fixed effects only) drawn dashed on screen and in PNGs.
- **I** ID mode matches tags as whole `_`-separated tokens (`TG` no longer matches inside `ATG1`).
- **J** Optional log-scale Y axis.
